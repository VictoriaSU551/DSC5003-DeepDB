## Estimator and budgets

Each query has independent deterministic table streams derived from SHA256(method, SQL SHA, seed1, query index, table). ID candidates are uniform integers between the live unconditional MIN and MAX. Every tested ID, including a hole, is removed from subsequent candidate lookups; RNG repeats consume attempts but issue no duplicate lookup. Stopping at k=min(1000,N) existing unique entities produces SRS without replacement on entity rows, including NULL predicate/FK values. Base lookup has only `id = ANY(...)`; predicates never guide sampling. COUNT/DISTINCT/MIN/MAX and the valid non-NULL PK gate establish the population instead of assuming dense IDs. The six live metadata queries are shared within the one locked RR snapshot and their full cost is reported separately.

The sampled SQL applies the original integer conjunctions only after ID selection. Each child is grouped by movie_id over its sampled rows; numeric multiplicity products are summed over sampled title IDs. It never materializes the full prefix join. The independent auditor implements SQL WHERE NULL rejection, strict boundaries and duplicate FK multiplicities in Python with arbitrary precision integers. For sampled join cardinality J and actual selected sizes k_i, the raw point is the exact Fraction `J * product(N_i / k_i)`. This is the independent base sample estimator for the registered no-alias title stars, not uniform sampling of joined tuples.

Every query's clock starts before SAVEPOINT, RNG/rejections and all base lookups, then includes statement-limit roundtrips, filtering/join, release, Fraction construction and any cleanup. Three of the2000 SQL roundtrips are reserved for failure cleanup, leaving1997 admission slots. SET statements and failed statements are counted. A watchdog cancels only its current owned connection at the30s deadline; a per-statement timeout is at most5s and decreases with remaining wall budget. Cancellation/rollback may finish after30s and that actual overrun remains in wall_seconds; no completed point is admitted at/after30s. Failed cleanup taints the whole attempt. Resource stops are permanent and taint the attempt rather than becoming attractive null measurements. The same live RAM/disk guard continues during postflight file hashing/math with no DB cancel target after the connection closes. Its guard windows are bounded to5400s each.

Terminal statuses: COMPLETE, COMPLETE_ZERO, STATEMENT_TIMEOUT (SQLSTATE57014), QUERY_WALL_BUDGET, ID_ATTEMPT_BUDGET, SQL_ROUNDTRIP_BUDGET, QUERY_ERROR. The final five failure classes have null sample_cardinality/raw_prediction, never a substituted truth or zero. All70 remain in predictions.json. Positive-truth q-error of a genuine zero is infinity. A partial result must retain its70-query denominator and report gaps; this code does not read a truth CSV or implement a scorer that can silently drop nulls. A future consumer must explicitly separate these raw-zero semantics from Scalar floor1.
