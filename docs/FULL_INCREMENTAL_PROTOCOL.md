# 年份更新实验

入口为 `code/full_incremental.py`。采用原 JOB-light schema 的 B=0 基础模型集合，
切点为2019、2011、2009、2004、1991。正式请求每模型至多10M行；
有限母体小于目标时使用全部行，实际样本数逐模型记录。

## 样本、时间划分与母体

每个模型先生成一份固定全量时间范围的训练样本，所有切点共用它。
准备矩阵与年份在 `data/imdb/temporal_samples/`，原数据保持只读。
正式协议采用超采样系数2，均匀缩减后严格要求行数等于
`min(请求样本数, 全外连接母体行数)`；不足即失败，不能以10M标签掩盖欠采样。

关系模型按 `title.production_year` 划分；单表子表通过完整主外键映射取得电影年份，
年份不进入子表模型的新增特征。未知年份/NULL哨兵归初始部分，保证每行恰好属于一组。
完整表及每个初始时间段的母体大小分别精确计算，连接使用全外连接的fan-out计数。

每个阶段绑定实际HDF内容、完整元数据、原始manifest、算法源码和所用辅助驱动的SHA256。
样本本身另封存values/years摘要。输入或辅助代码变化即拒绝复用。

## 更新与恢复

初始模型用RDC=.3、最小行簇1%训练，保留 `before.pkl`。
更新只改变叶分布、节点计数与和节点权重，路由中心和树结构固定。
为了避免数百万次Python逐行调用，按原固定中心批量路由，再合并直方图及计数。
原数值叶均值、逆均值、二阶矩由同一更新后分布重算。

测试将批量路径与未改的原逐行更新比较，覆盖新数值、NULL、分类值、距离并列和中断恢复。
每个正式树另外从实际更新区间抽取最多128行，先通过逐节点参数差分门禁，才接纳批量更新。
该实现是等价参数归并适配，不声称与逐行浮点加法逐位相同。

每10万更新行提交独立模型文件与SHA256、已完成游标和耗时历史，原子替换检查点。
恢复检查游标回执和模型摘要，仅处理未提交部分。每批及最终检查结构有效性。
最终 `full_sample_size` 必须等于初始加更新样本数；`full_join_size` 恢复为精确完整母体大小，
不把新增抽样行数错加为完整数据库行数。

完成后模型在 `output/full/models/temporal_joblight_*`，组件和恢复点在
`output/full/incremental/`，以v2推理策略评估70条JOB-light。

## 与论文数字的差异

论文Table2报告4.7/9.3/19.7/40.1%更新比例，本地不能直接套用这些标签。
PostgreSQL11.5对本快照独立计数：title共2,528,312行，NULL年份72,094行；
年份不小于2019/2011/2009/2004/1991的行数分别为
2 / 391,666 / 662,065 / 1,192,518 / 1,749,032。
不同连接母体和子表还会产生不同更新比例，正式结果分别保存实际比例。
公开原驱动另有用 `aka_title` 统计比例的代码；这不足以证明论文比例差异的唯一原因。

早期1000行门禁已完成25个初始/更新模型及70条评估，但一份实际样本为916行。
这只证明小规模执行与恢复，不计为论文规模。其源码版本保存在提交 `f49abba`；
正式v2加入依赖/实际HDF绑定和严格样本量条件，没有因升级而重算该旧门禁。
