# SSB SF500 可审查执行入口

本阶段实现原规模入口与SF2原流门禁，**不执行SF500，不重算SF1**。
此前的`full_ssb_generate.py`、SF1回执及34个镜像原文件均保持不变。

## 设计与实施计划

使用既有便携GCC及单进程dbgen分段驱动，保留原始种子、事实构造和历史缩放公式。
每次只物化一个连续订单段，消费完成后保留13条查询的整数聚合与独立哈希抽样，
原子提交检查点后删除该段；不物化3B事实表。
正式SF500使用约4000片，目标Bernoulli样本率为10,000,000/3,000,028,242。
样本数是随机实现值，不能承诺恰好10M。

- [x] 实现`code/full_ssb_paper.py`及测试；只恢复缺少的固定源码，不覆盖已有源码。

## SF2金标准门禁与一次真实失败

第一次SF2运行的16个事实段已经与未改stock `-s 2 -T a` 的完整管道输出相同，
但独立运行`-Ts`和`-Tc`生成的维表与stock不一致，门禁正确报告FAIL。
失败回执、错误维表及原stock维表保留在：

- `output/full/ssb/paper/sf2_gate/gate.json`
- `data/ssb/sf2_gate/dimensions/`
- `data/ssb/sf2_gate/stock_pipe/`

根因在原`build.c`：`gen_city`使用流98，经原`UnifInt`回退到PART流0；
`mk_supp`的电话也使用`C_PHNE_SD`。因此维表必须保留stock的
**part→supplier→customer→date**执行顺序，不能把四个单表进程当作原stock维表。
本任务增加独立`full_dimension_driver.c`，先调用原main的`-Tp`初始化并生成part，
随后按原顺序调用原`gen_tbl`，不调用事实构造，不更改原随机流或34个原文件。
原`gen_city`流索引等历史行为保留，未静默修补。

修复后另存`sf2_gate_v2`，避免覆盖失败证据。实际结果：

| 项目 | 实测 |
|---|---:|
| 原stock完整事实行数 | 11,998,051 |
| 原stock管道总字节 | 1,162,293,975 |
| 连续订单分片数 | 16 |
| 最大原始单片字节 | 73,259,696 |
| 固定seed、p=.003333样本行数 | 39,712 |
| 四维表逐字节比对 | 全部相同 |
| 16段覆盖完整stock原流 | 全部相同 |
| 第2片后追加未提交尾部再恢复 | 通过；已提交片保持不变 |

通过回执为`output/full/ssb/paper/sf2_gate_v2/gate.json`；stock完整流只经过命名管道，
没有完整SF2事实CSV。分片消费保留13条查询的整数聚合；SF2未另外运行独立SQL真值，
不把C++自聚合称为第二套SQL金标准。独立SQL金标准是此前已封存的完整SF1回执。

实际SF2维表生成1.053秒，16片原生成26.947秒，原生消费56.527秒，
分片处理总计85.692秒；stock管道完整遍历46.554秒。
当前并行任务会影响时间，以上不是独占硬件基准。
本任务保留的数据/输出约215.2MB，额外单片瞬时空间不足74MB，总计低于1GB新增预算。

## 绑定、恢复与正式输出

`compiled_binding()`绑定34个原文件、三个本地适配器和编译产物、GCC、
本入口与只读SF1辅助模块、查询SQL、作者原规模truth、固定生成器种子策略。
每个运行检查点另外绑定scale、分片数、抽样seed/概率、四维表的原字节摘要。
正式抽样seed=20261030，生成器沿用原`rnd.h`种子，二者互不推进。

`stream()`每次生成一个连续订单段，C++读完后输出分组整数SUM与样本。
样本追加后先fsync，再原子提交包含所有已完成片的检查点，最后删除原片及片内样本副本。
仅保留一个全局样本、四维表、每片小型整数聚合/统计/摘要；不保留3B事实CSV。
恢复先校验输入绑定、连续片号、所有聚合文件与行数/样本数/字节数账目，再验证样本已提交前缀SHA，
只截去未提交尾部。检查点之后、删除之前留下的已提交原片必须摘要相同才清理。
进程崩溃会自动释放OS文件锁，第二个写入者被拒绝。

维表作为同一原始序列生成，按文件原子提交并核验。全部完成后恢复不再生成维表；
若首次维表组尚未完成即崩溃，可能重新计算该维表序列以保留共享随机流，
已有完整维表保持原字节，只提交缺失表，并清理相同的暂存副本。
正式预算因此为维表额外预留一份恢复暂存，而不是假定任何中断都零成本。

正式目录为`data/ssb/sf500_paper/`及`output/full/ssb/paper/sf500/`，
结果为`output/full/results/ssb_paper.json`。
本阶段上述两个SF500目录均未创建。

## 已封存的SF500计划与成本

`output/full/ssb/paper/sf500_plan.json`为READY_FOR_ROOT_REVIEW。
4000片各约187,500个订单，预计每片事实CSV约72.6MB，硬上限256MiB。
生成器订单共750,000,000；事实行完成门禁仍为3,000,028,242，不能用约3B代替。
正式抽样概率为：

`0.00333330195362874187235734696126903994659128`

期望样本10,000,000行，实际数量以确定性独立抽样实现值为准。
SF500维表预期customer15,000,000、supplier1,000,000、part1,800,000、date2,556行。
原自然log事实part外键上限1,400,000与log2维表1,800,000差异保留。

| 预算 | 字节 |
|---|---:|
| 维表估算 | 1,677,378,803 |
| 维表恢复暂存额外预留 | 1,677,378,803 |
| 样本含20%余量 | 1,162,482,782 |
| 原始单片硬上限 | 268,435,456 |
| 新增峰值含其他余量 | 5,322,546,756 |
| 既有SSB加新增峰值 | 6,596,192,353 |
| 启动所需空闲磁盘 | 7,470,030,404 |

原生内存规划预算1.5GiB；SF2观测到峰值提交约944,152KiB，
SF500更大的维表数组会额外占用内存。该数是规划估计，不是已测SF500峰值或硬内存限额。
SF500每片前还要求保留2GiB磁盘空闲；总存储计划小于10GiB。

按实际SF2生成和消费时间作250倍线性外推，约20,868秒（5.80小时）；
用于排程的宽区间为14,608–41,737秒（4.06–11.59小时）。
维表、启动、摘要、检查点及机器争用另有开销，不把此估计当作实测SF500时间。

只有**事实行数完全相同且13条查询全部2,059个作者分组整数值相同**才写原规模数据门禁PASS。
否则写MISMATCH，保留结果并停止“作者母体已恢复”的声明。
即使该门禁PASS，也不代表模型训练、Fig9–13或完整论文复现完成。

.venv/Scripts/python.exe code/full_ssb_paper.py sf2-gate
