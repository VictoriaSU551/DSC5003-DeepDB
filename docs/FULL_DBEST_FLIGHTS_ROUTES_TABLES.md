# Independent DBEst Flights route tables

ROOT approved this small design for inline TDD. Only the new consumer, its dedicated tests and this document change; the seven scientific route sources and all old results remain frozen.

The consumer accepts only a completed `FORMAL_1B` `ROUTES` run. It invokes `full_dbest_flights_routes_audit.verify(home)` exactly once. That strict verifier already includes the complete original76-call evidence audit in the same boundary. The consumer does not invoke a second legacy audit, source proof, fit, integral, model loader, sample scan or database operation. A200K golden is deliberately rejected rather than combined with the old1B results.

After acceptance it reads only source-bound small JSON: the accepted final/seal/lifecycle, plan, queries, worker, support and evaluation descriptors; the original four-class report under the plan's already verified source closure; and the exact formal truth under `population_inputs`. Sources, physically consumed records, held-out labels, accepted final seal, explicit truth-identity aliases and policy determine a new derived binding. The result is an independent `output/full/figures/dbest_routes_<binding-prefix>/` containing query coverage, group results, native component states, Markdown and a self-sealed manifest. Existing outputs are reused only when their exact nonempty set and deterministic bytes match after a fresh strict verification. No old figure/table/pointer is changed and no plot is created.

Truth identity delegates once to the frozen V4 pure `validate_truth_identity(truth,population_rows=1000000000)` helper. It requires the exact12 SQL/no/name identities apart from its single explicitly named source-bound query3 literal: the sealed1B truth uses one space after `AND`, whereas the route source uses two. The source `SQLS` tuple and raw label file remain unchanged. The returned `SOURCE_BOUND_QUERY3_SINGLE_SPACE` metadata, including both literal SQL strings, are retained in the derived binding/manifest and summarized in Markdown. CSV rows distinguish that accepted identity from `EXACT_LITERAL`. No other SQL whitespace, predicate, population, query number or name is normalized. This does not merge query7's fitting-configuration variant with any author method.

All12 original query identities remain visible. Old F1.1/F1.2/F3.1/F4.1 are explicitly historical76 calls, not rerun calls. The three pure-category COUNT cases and the multidimensional case remain unsupported. New1D routes report actual calls, fit attempts, empty fixed-subset components, fit errors, native errors, NULL/nonfinite/numerical-budget/validation gaps and their group coverage. The fixed20K fitting subset is not the whole information budget: new metadata use complete retained-sample category/non-NULL counts divided by p; old four-class metadata retain their separately declared full-stream/count or estimated-state scope. Target aggregate labels are evaluation only, not training counts or features.

F3.3 query7 retains `public_prefilter_matches=false` and `QUERY_AWARE_EXACT_YEAR_PREFILTER_VARIANT`. The published target SQL, route target SQL and formal1B label SQL all require `year_date=2005 AND origin='PHX'`. The flag describes the fitting-prefilter configuration, not an evaluation-SQL mismatch. Its finite points may therefore be scored against the strictly matching exact full-population truth. Query and group CSV rows separate `evaluation_sql_match=true` from `author_prefilter_config_match=false`; Markdown gives the LOCAL F3.3 variant its own table. These results do not identify the author's training configuration and do not enter a shared method ranking. Any actual target SQL/no/name mismatch remains a rejection, including query7. The original sealed evaluation's numeric errors are not reused; errors are independently derived from the accepted raw predictions and exact labels. F5.2 query11 remains two original SUM point estimates and their difference; the difference has no joint CI or invented component truth. Raw component statuses are separate from final difference availability.

For eligible queries, group keys preserve NULL versus strings, raw signed/zero estimates and exact rational truths. Missing, present-but-unavailable, invalid points, extra groups and zero truths remain distinct. `matched_conditional_mean_relative_error` is conditional on finite matched nonzero truths and explicitly accompanies coverage. `all_nonzero_truth_mean_relative_error` is null unless every truth group has a finite point and no extra group exists. No missing/error point is silently imputed as a100% prediction and no conditional statistic is called full coverage. Relative errors use absolute truth magnitude; zero truths retain absolute errors but have no relative error. This independent policy is not a replacement for the old figure's declared100% missing-group penalty.
