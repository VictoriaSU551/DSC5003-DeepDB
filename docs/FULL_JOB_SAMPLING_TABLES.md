# Independent LOCAL JOB70 sampling tables

`code/full_job_sampling_tables.py` is a standard-library consumer for separately supplied, already sealed LOCAL SRS and/or IBJS results. It does not sample, estimate, query a database, load a model, call the Scalar estimator, or amend an earlier result. These variants do not identify the author's Table1 configuration and are not placed in a shared author ranking.

Each public `build(directories, root=ROOT)` calls the selected frozen `full_job_sampling_audit.verify` or `full_job_sampling_ibjs_audit.verify` exactly once. Even deterministic reuse performs a fresh verification. There is no supplied-proof, cache, repair or verification-skip API. The source inventory pins accepted SRS V4 and Scalar V4 sources; selecting IBJS also pins its accepted pure kernel and runtime. The consumer checks the actual loaded auditor path. Its own three files are included by current physical SHA, without copying source trees.

Development used only synthetic receipts and counted verifier stubs. Neither a real verifier nor an exporter over scientific results was executed. The pure scorer first failed because the new module was absent; the integration gate then failed because the source/acceptance interface was absent. The dedicated final suite has 35 passing pure/fixture tests. An initial fixture-only Python3.8 `Path.write_text(newline=...)` incompatibility was corrected before the integration RED evidence. Tests include complete70 and incomplete70, zeros and infinity, exact rational interpolation, wrong SQL/labels, missing/duplicate/subset physical closures, semantic damage after resealing, changed sources, one acceptance per method, immutable input bytes/mtimes, forbidden scientific imports, and refusal to repair existing exports.

Only ROOT may run the actual export after scientific acceptance:

```powershell
.venv/Scripts/python.exe -B code/full_job_sampling_tables.py --srs-run <sealed-SRS-run> --ibjs-run <sealed-IBJS-run>
```

Either method may be omitted; an empty selection is refused. Input paths must be the method's exact binding namespace. Required files are independently enumerated: SRS147 plus its final seal; IBJS148 plus its final seal. Final and query seals, unique complete physical descriptor sets, current bodies, PASS lifecycle, binding, fixed LOCAL configuration, complete ordered70 identities and reported coverage are checked. The fixed SQL SHA is `e61da91710ce62d3669be70a8ded2499c6de1d759fcfac9a954b939465e76fdb`; official positive labels and the PostgreSQL11.5 independently confirmed label CSV/receipt have separate literal pins. Labels are read only by this post-processing consumer, never supplied to either estimator. The frozen auditor is responsible for its complete dependency/runtime replay; the consumer rechecks its source, label and accepted publication files before and after derivation.

Each method retains all70 rows with its original raw numerator/denominator, status, SQL and query number. A positive truth and zero estimate have q-error `Infinity`, a legal JSON string with an explicit metric status; unfinished predictions remain null. No floor1 is applied. Whole70 median/p90/p95/max exist only if all70 queries completed and include infinite errors. Linear extended-real interpolation returns an exact endpoint before interpolation; any positive interpolation weight on infinity gives infinity. It never computes zero times infinity. Finite-only summaries always expose their conditional count, and unfinished/status/zero/infinite counts remain visible. No completed subset is represented as a whole70 result.

SRS is labelled `LOCAL_JOB70_SRS_WOR_N1000`; IBJS is `LOCAL_JOB70_IBJS_SQL_N1000_B100K`, with n1000, b100000, and its LOCAL adaptive stop-after-complete fallback visible. Author configuration and adaptive-path unbiasedness are not claimed. Every query retains client wall, SQL roundtrips, ID attempts, operation kind/duration/status/cleanup, base lookup calls, fanout-count calls, kth-rank calls and IBJS logical lookups. Physical rows scanned are unknown, not zero. Common SRS65 =17 setup/identity/metadata/reset +36 schema +12 binary COPY; IBJS67 =19 setup/identity/metadata/index/reset +36 schema +12 COPY. Both full six-table projection passes and their bytes are separate from online cost. Metadata/preparation, leaf-checkpoint wall, controller admission/postflight/validation and measured client wall remain separate. No external command wall is supplied through this API; it is null, explicitly unavailable, and no end-to-end/free-oracle latency is asserted. Query-column snapshots and historical import lineage do not claim full original CSV value identity or a current live database recheck.

Output is confined to a new `output/full/figures/sampling_<binding20>/` directory containing exactly `predictions_scored.csv`, `method_costs.csv`, `RESULTS.md`, and `manifest.json`. The small manifest binds inputs, accepted verification/final-seal descriptors, scope/configuration, exact evaluation policy, method summaries, cost ledgers and deterministic output hashes, with its own self hash. Original files are never overwritten. Existing output must match the complete deterministic four-file set byte for byte after fresh acceptance; extra/missing/tampered files fail, including interrupted writes. Input changes fail the derivation. No previous paper table, Scalar table, publication pointer, failed run or scientific receipt is modified.
