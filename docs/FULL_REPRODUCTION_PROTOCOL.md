## 方法理解

1. 第 3.1 节：和节点划分行簇，积节点划分近似独立列；KMeans 划分行，RDC 检测列依赖。
   最小行簇为训练样本量的 1%，RDC 阈值 0.3。
2. 第 3.2 节：RSPN 扩展条件期望、SQL NULL、数值叶节点频数及函数依赖映射。
   函数依赖不是额外独立性假设：它把被省略列的条件转回保留列。
3. 第 3.3 节：对相关的主外键表训练全外连接模型，保留无匹配的原始记录；否则训练单表模型。
4. 第 4.1 节：COUNT 查询通过 `|J| * E[1/F'(Q,J) * 1_C * product(N_T)]` 计算。
   `N_T` 排除外连接补出的行，连接倍数 `F'` 修正重复。多个模型的组合仍依赖文中明确的条件独立假设。
5. 第 4.2 节：AVG 使用经连接倍数修正的两个条件期望之比；SUM=COUNT*AVG；GROUP BY 逐组估计。
   跨模型 AVG 会忽略模型之外的部分条件，存在近似误差，不能声称一般情况下精确。
6. 第 5.1 节：CI 依赖概率与期望估计独立、结果近似正态的假设；差值 SUM（Flights F5.2）会违反前者。
7. 第 5.2 节：更新只改变权重/叶分布，沿最近 KMeans 中心下传，不自动改变结构；新依赖需要重建。
8. 第 5.3 节：按跨表 RDC 与列数平方、样本量的成本关系选择额外模型，预算以基础模型成本为参照。

## 必须明确的论文与公开代码差异

- 正文第 6 节写预算 **B=0.5**，公开 README 示例为 **5**，CLI 原先只接收整数。
  本轮允许浮点预算，分别记录正文配置与 README 配置，不把 5 当作 0.5。
- 正文基数估计默认 **10M** 样本，存储优化模型为 **100K**、仅基础模型。
  旧结果为 **1M** 样本的关系基础模型，不能直接对应 Table 1 的两个 DeepDB 条目。
- 论文提到 200 条随机查询，必须清点公开文件实际条数、分组和 SQL/真值对应关系；不得凭文字推定数量。
- 公开代码用列数平方和随机候选近似选择模型；这与正文基于实际训练时间的预算叙述不完全相同。
  忠实运行公开代码与另行实现论文描述必须分开记账。
- 连接模型训练样本为全外连接；公开代码用于标定模型的数据库查询却是内连接。
  比较两种连接的基数，记录其影响，不悄悄替换实验定义。
- 公开 scale 查询中的 157 条包含 `cast_info.person_id`，但官方 `imdb-light` schema 把它排除了。
  原 profile 保留给 JOB-light；新增 `public-scale` profile 仅补回此列并重新训练所需模型。
  两类结果不混用；新 profile 的连接基数与其余原始表不变。
- 本地大样本训练使用精确全外连接母体大小决定父表采样率，超采样系数 1.05，随后缩减到目标样本量。
  这是为内存安全记录的本地适配，不能宣称恢复了作者未固定随机种子的具体训练样本。
- 单组件采用稳定摘要产生的随机种子，保证跳过已完成组件不会改变后续组件的随机状态。
