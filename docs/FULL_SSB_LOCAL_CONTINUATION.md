# LOCAL canonical continuation

This is a new execution contract, `ADOPT_ACCEPTED_FORWARD_FRESH_REVERSE_WITH_CONSUMED_CLOSURE_V1`, under scope `LOCAL_SSB_SF500_CANONICAL_CONTINUATION`. It preserves the frozen original formal model and canonical providers. The old canonical ROOT/reverse controls remain TAINTED. No training, preparation, moments calculation, generation or FORWARD inference is repeated.

The prerequisite is the exact reviewed old plan, a fresh direct original `verify_local_formal` proof, frozen `canonical._verify_phase(old_plan, 'FORWARD', parent)` and frozen `runner.verify_child(old_plan, 'FORWARD')`. Thus the adopted FORWARD retains its real26 calls, one model load,13 SQLs,2059 groups, query seals and owned-process evidence. Its physical files and old plan are bound in the new plan. Only the recorded stale-before-reverse history with no old `reverse/` scientific directory is eligible. The three failure provenance records are ROOT-only historical evidence, never worker inputs and never a repaired ROOT PASS.

The scientific worker has an explicit new contract. It verifies current model, adopted FORWARD/query JSON+seals, truth projection, moments, exact inference algorithm/SPFlow/parser sources, package versions, actual module roots, physical native libraries, base Python, venv and the two new modules. It does not recursively verify the raw sample, dimension data,4000 generation chunks or compiler distribution. This is not a shortcut accepted by an old API: ROOT pre/post each run the complete original F. Public `verify_canonical()` runs exactly one complete original F and returns its complete original `parent_snapshot` with `proof_method='DIRECT_FROZEN_PREVIOUS_VERIFY_LOCAL_FORMAL'`, plus the union of all original, accepted FORWARD and new artifacts. No external skip flag, cached proof or persisted fake original PASS is accepted.

After every inference import/context has entered, the fresh owned venv worker seeds Python/NumPy74031, with hash173 and all four thread limits1. It uses the unchanged paired group adapter SHA48220a0474a838c8dc9a7cf3fef0e8a84459a05e3fa8e15405307acae430ae5c and frozen `execute_query` in order12..0. Each query reloads the model and actually calls point and CI evaluation:13 loads/26 calls. Actual query JSON is saved before comparison, so a failed numeric comparison retains diagnostic values. Frozen comparisons preserve missing/nonfinite/CI-state rules and the original tolerances. The original raw/prepared reader guard remains active.

Operational admission remains5GiB available RAM at launch,4GiB in the worker,6GiB owned RSS,1GiB live available RAM,8GiB free disk,16GiB combined SSB storage,512MiB output reserve and48h wall time. The frozen kernel Job Object/direct-base→GO→original-venv primitives are reused. A new small monitor wrapper keeps the original90s stale limit and records walk duration, progress heartbeat, final resource probes and bounded cleanup errors. A stale scan still fails. The first exception is retained even when terminate/wait/join cleanup also fails. ROOT admission refreshes fast RAM/free-disk after the complete storage walk. RUNNING, TAINTED or already completed namespaces are never repaired/reexecuted; completed results use read-only verification. Publication has its own transaction, and any post-F/publication failure taints the whole new ROOT transaction.

The new plan/run namespace is `output/full/ssb/local_sf500_continuation/`. The stable, previously unpublished result alias is `output/full/results/ssb_local_sf500_canonical_aqp_ci.json`.
